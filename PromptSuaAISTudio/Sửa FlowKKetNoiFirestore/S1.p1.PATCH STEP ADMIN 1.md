PATCH ADMIN LICENSE – STEP 1.1
HARDEN SIGNING KEY STORAGE

QUAN TRỌNG:

STEP ADMIN 1 đã được triển khai và có thể đã tạo Signing Key Pair.

KHÔNG generate Signing Key Pair mới nếu key hiện tại đã tồn tại.

KHÔNG thay đổi thuật toán.

GIỮ NGUYÊN:

ECDSA
P-256
SHA-256

Flow App hiện tại đã sử dụng Public Key tương ứng để verify License Token.

Nếu regenerate key mới sẽ làm Flow App không verify được Token,
vì vậy tuyệt đối phải bảo toàn key pair hiện tại.

==================================================
1. KIỂM TRA KEY HIỆN TẠI
==================================================

Trước tiên kiểm tra document hiện tại:

system/licenseSigningKeys/current

Nếu document này đang chứa:

keyId
algorithm
curve
publicJwk
privateJwk
createdAt
createdBy
status

thì đây là Signing Key Pair hiện tại.

KHÔNG generate key khác.

Giữ nguyên:

publicJwk
privateJwk
keyId

==================================================
2. TÁCH PUBLIC KEY VÀ PRIVATE KEY
==================================================

Chuyển cấu trúc thành:

PUBLIC KEY DOCUMENT:

systemPublic/licenseSigningKeys/current

Fields:

keyId
algorithm
curve
publicJwk
createdAt
createdBy
status


PRIVATE KEY DOCUMENT:

systemPrivate/licenseSigningKeys/current

Fields:

keyId
privateJwk
createdAt
createdBy
status

CẢ HAI document phải sử dụng cùng keyId.

Không thay đổi nội dung cryptographic key.

==================================================
3. MIGRATION
==================================================

Nếu key pair hiện tại đang nằm tại:

system/licenseSigningKeys/current

thì migrate chính key pair đó sang 2 document mới.

KHÔNG gọi:

crypto.subtle.generateKey()

trong quá trình migration.

Sau khi migration phải xác nhận:

old publicJwk === new publicJwk

old privateJwk === new privateJwk

old keyId === new keyId

Chỉ khi tất cả MATCH mới coi migration thành công.

Chưa cần xóa document cũ ngay.

Có thể đánh dấu:

migrated: true

để tránh mất dữ liệu ngoài ý muốn.

==================================================
4. FIRESTORE SECURITY
==================================================

Admin hợp lệ khi:

request.auth != null

và:

users/{request.auth.uid}.afrole == "afadmin"

PRIVATE SIGNING KEY:

systemPrivate/licenseSigningKeys/{document}

Chỉ AF Admin được exact GET.

Không cho anonymous.

Không cho user thường.

Không cần LIST.

Không được expose private key qua public query.

PUBLIC SIGNING KEY:

systemPublic/licenseSigningKeys/{document}

Có thể chỉ cho AF Admin đọc ở Admin Web,
vì Flow App sẽ nhận Public Key bằng cách nhúng vào source.

Không cần Flow App truy cập Firebase.

==================================================
5. ADMIN SIGNING SERVICE
==================================================

Khi Admin cần ký License:

1. Xác nhận Firebase User đang login.
2. Xác nhận afrole == afadmin.
3. Exact GET:

systemPrivate/licenseSigningKeys/current

4. Lấy privateJwk trong memory.
5. Import bằng Web Crypto.
6. Ký Token.
7. Không lưu privateJwk vào localStorage.
8. Không lưu privateJwk vào sessionStorage.
9. Không console.log privateJwk.
10. Không đưa privateJwk vào React state lâu dài nếu không cần.

Sau khi ký xong:
không persist Private Key ở client.

==================================================
6. PUBLIC KEY CONFIGURATION
==================================================

Trang Signing Key Management vẫn hiển thị:

Key ID
Algorithm
Curve
Created At
Status

Section:

PUBLIC KEY

Hiển thị publicJwk.

Button:

COPY PUBLIC KEY

"Public Key này được nhúng vào Flow App để xác minh License.
Không đưa Private Key vào Flow App."

KHÔNG hiển thị privateJwk.

KHÔNG có button Copy Private Key.

==================================================
7. KEY VERSIONING
==================================================

Giữ field:

keyId

Ví dụ:

af-license-2026-01

Không tự rotate key.

Không tự tạo key mới theo tháng/năm.

Một key pair hiện tại có thể được sử dụng lâu dài cho nhiều Project App.

Mỗi License Token sau này phải chứa:

keyId

để biết Token được ký bởi key nào.

==================================================
8. CHUẨN BỊ TOKEN METADATA
==================================================

Chưa tạo Token ở step này.

Chỉ chuẩn bị constant/config cho:

TOKEN_VERSION = 1

LICENSE_ISSUER = "aifast-license-admin"

LICENSE_AUDIENCE = "aifast-flow-offline"

Các giá trị này sau này sẽ được đưa vào signed payload.

Không thay đổi Flow App trong step này.
